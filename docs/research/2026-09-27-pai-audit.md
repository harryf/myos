## 2. Security pipeline

Files: `hooks/security/pipeline.ts` (115 lines, priority-ordered chain, deny short-circuits, approval accumulates, inspector errors are skipped), `types.ts`, `logger.ts` (writes `PAI/MEMORY/SECURITY/YYYY/MM/`, 15 MB so far), `inspectors/PatternInspector.ts` (220 lines, reads `PAI/USER/SECURITY/PATTERNS.yaml`, fail-closed if the YAML is missing), `EgressInspector.ts` (77 lines, hard-coded credential and outbound regexes duplicating the YAML), `RulesInspector.ts` (117 lines, LLM evaluation of `SECURITY_RULES.md`, file does not exist so it is inert), `InjectionInspector.ts` (PostToolUse content), `PromptInspector.ts` (UserPromptSubmit).

What `PATTERNS.yaml` blocks (silent deny, exit 2), described rather than quoted because quoting the strings trips the hook (see below): recursive deletion of root, home, `~/.claude`, `PAI`, `PAI/MEMORY`, `~/Projects`; the diskutil erase and zero commands, dd zero-fill of a device, filesystem formatting; deleting the patterns file, the SecurityPipeline hook or settings.json; GitHub repository deletion and flipping a repo public via gh; any command string containing an outbound tool name (curl, wget, nc, fetch, http) together with a Stripe, Anthropic or OpenAI key prefix, PEM key material or a webhook secret prefix; piping a downloader into a shell. Alerts (log and allow): piping into a shell with -c, force push, hard reset, DROP and TRUNCATE, terraform destroy, HTTP POST via curl or wget, netcat, ncat, socat, sendmail, inline python, node, ruby and perl one-liners, env or set dumps, cat, grep or source on a `.env` file. Path rules: zero access to `~/.ssh/id_*`, `~/.aws/credentials`, `~/.gnupg/private*`, `**/service-account*.json`; alert on any `.env`; read-only on `/etc/**` and the security files themselves; noDelete on `~/.claude/hooks/**`, `~/.claude/PAI/**`, `.git/**`. Trusted prefixes: `playwright-cli`, `bunx playwright`, `agent-browser`, deleting the PAI_RELEASES staging dir.

Known false positives:

- The root-deletion regex (`PATTERNS.yaml` `bash.blocked[0]`: the letters r, m, whitespace, then anywhere later a dash-flag containing r, then anywhere later whitespace, a slash and whitespace or end) is tested against the whole command string, not the first token. So `rm\s` matches inside "form ", "term ", "confirm ", and the trailing slash matches any " / " separator. A heredoc, a sed or rg argument, or a commit message can trip it. This is the case Harry hit (a heredoc containing a leading-slash regex read as deleting root, noted in PROJECTS.md under the Meta video ads entry; workaround was the Edit tool).
- Reproduced during this audit: the first attempt to save this report through a Bash heredoc was blocked with "Disk overwrite with zeros" because the text quoted the dd pattern; the literal `gh` and key-prefix patterns would have blocked it too. Any documentation of the patterns cannot pass through Bash.
- `python3 -c` alerts on every one of the auto-mode Bash-first helpers; harmless but noisy in `MEMORY/SECURITY`.
- HTTP POST via curl alerts on every Grist, Meta and Eventfrog API call Harry's scripts make, which is most of his real work.
- `PromptInspector` blocks the user's own prompt on "forget everything", "you are now a ..." (severity block). For a single-user system with no external prompt sources this only bites Harry.
- `**/service-account*.json` zeroAccess would block reading the GA service-account file the IYF scripts use if it were ever named that way (the crontab jobs run outside Claude so today it does not matter).

Worth keeping? Yes, as a 100 to 150 line hook: the deny list for destructive filesystem and disk commands, the secret-in-command-string check, and the zeroAccess paths. Drop the Rules inspector (LLM per tool call), the Egress duplication, the alert tier (write-only logging nobody reads), and PromptGuard. Anchor the recursive-delete patterns to a command boundary (start of string or after a semicolon, double ampersand or pipe) and test only the first token of each pipeline segment, and skip heredoc bodies, to remove the false positives above.
