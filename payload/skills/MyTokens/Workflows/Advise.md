# Advise: spend less, grounded in the log

Deliverable: ranked recommendations, each carrying its evidence from this user's own
data (the token log, `rtk gain`, `MEMORY/OBSERVABILITY/tool-activity.jsonl`, the
session's connector list) and an honest size of the win. No generic listicles: a lever
that the log shows this user doesn't pull gets dropped, not padded.

The levers, checked in this order:

1. **rtk missing or idle.** Shell output is the classic silent cost. `rtk gain` shows
   real savings; `which rtk` missing means the ContextReduction hook is a no-op. Fix:
   `brew install rtk`, nothing else.
2. **Expensive models on mechanical work.** The by-model split shows where Fable
   (roughly 2× Opus) and Opus go. Utility inference (`MYOS/TOOLS/Inference.ts`,
   Haiku/Sonnet) fits classification, extraction and formatting; fast mode fits routine
   Opus work.
3. **Idle MCP connectors.** Every enabled connector adds its tool schemas to every
   session, paid in cache writes each session start. Compare connectors enabled
   (claude.ai → Settings → Connectors) against connectors actually used
   (`tool-activity.jsonl`); recommend disabling the idle ones.
4. **Low cache efficiency.** Below ~90% suggests many short sessions with cold starts.
   Related work batched into one session rereads context from cache instead of
   rewriting it.
5. **Fan-out habits.** Activities with heavy `subOut`: subagents and workflows multiply
   output tokens. Worth it for verification and breadth; wasteful for work one context
   could hold. Point at the specific activities.
6. **Fat single activities.** The top-activities list names the sessions that dwarf the
   rest. Read what they were; often the fix is upstream (a report regenerated by hand
   each time, a file read whole instead of by range, a loop that should be a tool).

Close with the two or three changes worth making this week, not all six.
